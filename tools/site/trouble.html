Si quelque chose bloque

Collez le message à votre assistant IA, ou cherchez-le ici.

« les ports 80 ou 443 sont déjà pris »

Une autre application occupe le web du serveur, souvent une application Docker installée par le panneau de l'hébergeur (un agent IA, n8n, un panneau d'administration…). Voyez laquelle, puis arrêtez-la ou utilisez un autre serveur :

sudo ss -ltnp | grep -E ':(80|443) '
docker ps

Si c'est Traefik (le portier des applications Docker, par exemple sur un VPS Hostinger) : ne l'arrêtez pas, installez Dynamite | Agile derrière lui. Traefik garde les ports et donne le certificat HTTPS ; vos autres applications ne bougent pas. L'adresse doit pointer vers le serveur (chez Hostinger : dynamite.srvXXXX.hstgr.cloud).

curl -fsSL https://jpdesbiens11.github.io/Dynamite-Agile/install.sh | sudo bash -s -- --traefik dynamite.srvXXXX.hstgr.cloud
« le domaine … ne répond pas encore » ou certbot : « NXDOMAIN », « Timeout »

L'enregistrement A n'est pas encore visible, ou le port 80 est fermé dans le pare-feu du panneau. Vérifiez avec nslookup depuis votre ordinateur, ouvrez 80 et 443, attendez quelques minutes et relancez la même commande.

« Permission denied » à la connexion SSH

Mot de passe root erroné (rien ne s'affiche pendant la frappe, c'est normal). Choisissez-en un nouveau dans le panneau de l'hébergeur, ou utilisez sa console web.

« curl: command not found » 
sudo apt update && sudo apt install -y curl
« le service ne démarre pas »

Le script affiche les dernières lignes du journal : chaque refus nomme la valeur en cause et le correctif. Pour le revoir :

journalctl -u dynamite-agile -n 50 --no-pager
PC Windows : « PowerShell n'est pas ouvert en administrateur »

Fermez la fenêtre, puis Win + X → Terminal (admin) → Oui, et relancez la même commande.

PC Windows : « le port 443 est déjà pris par … »

Un autre service web occupe le port (IIS, un logiciel de visioconférence ou d'antivirus…). Arrêtez-le, ou installez sur un autre port :

powershell -ExecutionPolicy Bypass -File $env:TEMP\install-dynamite.ps1 -Port 8443
PC Windows : l'équipe n'arrive pas à ouvrir l'adresse

Le réseau du PC est marqué Public (Paramètres → Réseau et Internet → Propriétés → Privé), ou le nom du PC n'est pas connu du réseau : ouvrez plutôt https:// suivi de l'adresse IP affichée à la fin de l'installation.

« Votre connexion n'est pas privée » (NET::ERR_CERT_AUTHORITY_INVALID)

Ce poste ne connaît pas encore l'autorité de l'équipe : importez ca-dynamite.crt (étape « Faites confiance au certificat »), puis fermez et rouvrez le navigateur. Ne contournez pas l'avertissement.

Sur mon ordinateur : « python n'est pas reconnu » ou l'adresse ne s'ouvre pas

Fermez et rouvrez le terminal après l'installation de Python. Si le port 8080 est déjà pris, lancez avec --port 8090 et ouvrez http://127.0.0.1:8090.
