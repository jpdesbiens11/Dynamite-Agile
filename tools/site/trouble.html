Si quelque chose bloque

Collez le message à votre assistant IA, ou cherchez-le ici.

« les ports 80 ou 443 sont déjà pris »

Une autre application occupe le web du serveur, souvent une application Docker installée par le panneau de l'hébergeur (un agent IA, n8n, un panneau d'administration…). Voyez laquelle, puis arrêtez-la ou utilisez un autre serveur :

sudo ss -ltnp | grep -E ':(80|443) '
docker ps
« le domaine … ne répond pas encore » ou certbot : « NXDOMAIN », « Timeout »

L'enregistrement A n'est pas encore visible, ou le port 80 est fermé dans le pare-feu du panneau. Vérifiez avec nslookup depuis votre ordinateur, ouvrez 80 et 443, attendez quelques minutes et relancez la même commande.

« Permission denied » à la connexion SSH

Mot de passe root erroné (rien ne s'affiche pendant la frappe, c'est normal). Choisissez-en un nouveau dans le panneau de l'hébergeur, ou utilisez sa console web.

« curl: command not found » 
sudo apt update && sudo apt install -y curl
« le service ne démarre pas »

Le script affiche les dernières lignes du journal : chaque refus nomme la valeur en cause et le correctif. Pour le revoir :

journalctl -u dynamite-agile -n 50 --no-pager
Sur mon ordinateur : « python n'est pas reconnu » ou l'adresse ne s'ouvre pas

Fermez et rouvrez le terminal après l'installation de Python. Si le port 8080 est déjà pris, lancez avec --port 8090 et ouvrez http://127.0.0.1:8090.
