Installer Dynamite | Agile sur votre VPS

Un serveur Linux, un nom de domaine et trois commandes. L'exemple suit un VPS Hostinger (offre KVM), mais la procédure vaut pour tout VPS Ubuntu ou Debian.

1. Ce qu'il faut

ÉlémentMinimumRemarque
ServeurVPS Linux, 1 vCPU, 1 Go de mémoire, 10 Go de disqueUbuntu 22.04 / 24.04 ou Debian 12. Une équipe de 10 personnes tient à l'aise sur la plus petite offre.
AccèsSSH en root (ou un compte avec sudo)Ou la console web du panneau de l'hébergeur.
DomaineUn nom de domaine ou un sous-domainePour le certificat HTTPS gratuit (Let's Encrypt).
Ports22, 80 et 443 libresAucun autre site ni application ne doit déjà occuper 80 ou 443 sur ce VPS.

2. Préparer le VPS

  1. Choisir le systèmeDans le panneau de l'hébergeur (Hostinger : hPanel → VPS → OS & Panel), installez Ubuntu 24.04 sans panneau ni application, ou gardez celui en place s'il n'occupe pas les ports 80 et 443.
  2. Noter l'adresse IP et l'accès rootSur la page Overview du VPS : l'adresse IP, le nom d'utilisateur SSH (root) et le mot de passe root (bouton Change pour en choisir un). Mieux encore : ajoutez votre clé SSH.
  3. Ouvrir le pare-feu du panneauSi l'hébergeur a son propre pare-feu (Hostinger : Security → Firewall), autorisez les ports 22 (SSH), 80 et 443 (web). Le script règle ensuite le pare-feu du système.

3. Pointer le domaine vers le VPS

  1. Créer l'enregistrement ADans le gestionnaire DNS de votre domaine (Hostinger : DNS Manager, ou Claim your free domain sur la page du VPS), créez un enregistrement A : nom atelier (ou @ pour le domaine nu), valeur = l'adresse IP du VPS, TTL court (300 s).
  2. VérifierAprès quelques minutes, depuis votre poste : ping atelier.mon-domaine.ca doit répondre avec l'adresse IP du VPS. Le certificat HTTPS ne peut pas être obtenu avant.

4. Se connecter au VPS

Depuis un terminal (Windows : PowerShell ou Terminal ; macOS et Linux : Terminal), ou avec le bouton Web console du panneau :

ssh root@ADRESSE_IP_DU_VPS

5. Installer en trois commandes

Remplacez le domaine et le courriel (il sert seulement aux avis d'expiration du certificat) :

sudo apt update && sudo apt install -y git
sudo git clone {{REPO}}.git /opt/dynamite_agile
sudo bash /opt/dynamite_agile/deploy/install.sh atelier.mon-domaine.ca moi@exemple.ca
Ce que fait le script, dans l'ordre : paquets du système (Python 3, git, certbot, ufw) ; pare-feu (22, 80, 443) ; utilisateur système dynamite sans droits root ; certificat HTTPS Let's Encrypt, renouvelé tout seul ; data/config.json pour la production (HTTPS sur 443, redirection depuis 80, mode développement coupé) ; service dynamite-agile démarré au boot ; affichage du mot de passe temporaire du compte admin. On peut le relancer sans rien perdre.

6. Premier accès et votre équipe

  1. Se connecterOuvrez https://atelier.mon-domaine.ca, compte admin, avec le mot de passe affiché par le script ; choisissez tout de suite le vôtre.
  2. Créer les comptes⚙ Admin → Comptes → Règles d'accès : une ligne par personne, vérifiée à blanc avant d'être appliquée. Chacun reçoit un mot de passe temporaire à changer à la première connexion. 
    utilisateur nina | Nina | utilisateur | actif
profil      nina | Génie mécanique
droit       nina | EQP | admin-projet
  3. Créer le Space du projet⚙ Admin → Spaces : une clé (ex. EQP) et un nom. Le Space est prêt dans chaque onglet, avec une carte « Commencer ici ».
  4. Faire le tour guidéHelp → le tour du site, un chapitre par outil, avec son exercice dans le Space bac à sable HEADLAMP. Voir aussi le guide de prise en main.

7. Entretien

Pour…Faire
Mettre à jour le codesudo bash /opt/dynamite_agile/deploy/redeploy.sh (les données ne sont jamais touchées)
Sauvegarder⚙ Admin → Update et sauvegardes : points de restauration, sauvegarde d'un Space ; et la sauvegarde du VPS chez l'hébergeur
Voir le journal du servicejournalctl -u dynamite-agile -n 100
Redémarrersudo systemctl restart dynamite-agile
Mot de passe admin oubliésudo -u dynamite python3 /opt/dynamite_agile/app_dynamite_agile.py --reset-password admin
Vérifier HTTPS⚙ Admin → Sécurité réseau : HTTPS actif, TLS 1.3, HSTS
Déménager⚙ Admin → Update et sauvegardes → Site complet, vers un site neuf

Dépannage

MessageCause et correctif
« les ports 80 ou 443 sont déjà pris »Un serveur web ou une application installée par le panneau (souvent dans Docker) écoute déjà. Arrêtez-la ou installez Dynamite | Agile sur un autre VPS.
certbot : « Timeout during connect » ou « NXDOMAIN »Le domaine ne pointe pas encore vers le VPS, ou le port 80 est fermé dans le pare-feu du panneau. Vérifiez l'enregistrement A et le pare-feu, attendez la propagation, relancez le script.
Le service ne démarre pasjournalctl -u dynamite-agile -n 50 : chaque refus nomme la valeur fautive et le correctif.
Pas encore de domaineEssai privé par tunnel SSH : voir deploy/DEPLOIEMENT_VPS.md dans le dépôt.
